# Workspace 目录规范化为何不能替代文件访问授权？

复习优先级：高。参考答案已整理、尚未模拟。

## 参考答案与取舍

项目入口要求本机绝对路径，并用 resolve(strict=True) 得到已存在的真实目标，再检查目录类型。保留合法空格，不展开 ~ 或环境变量，避免输入被隐式解释；拒绝文件系统根目录，限制过大的项目范围。入口允许符号链接，保存其规范目标。

用户选择目录入口与工具访问目录内文件是两层检查。入口解析成功不代表目录内软链接都可访问；文件工具必须根据实际目标检查是否落在绑定根目录内，不能只按字符串前缀判断。路径检查和打开文件之间可能发生替换，即 TOCTOU；真正的执行边界还需要操作时校验、适当的文件描述符策略与进程隔离，不能声称一次 resolve 已实现 Sandbox。

## 失败场景

目录不存在、普通文件、路径中间不是目录、失效/循环链接、权限不足与其他文件系统故障要区分。使用稳定业务错误码，响应不直接携带原始系统异常；验证成功只描述检查时刻，不保证之后仍存在或可写。

## 并发绑定如何避免后来的请求覆盖项目目录？

按 Workspace 标识及归属 SELECT FOR UPDATE，锁内读取最新绑定值，再校验规范路径；首次绑定保存，同一规范路径重复成功，不同目录拒绝覆盖。所有绑定入口遵循该事务规则，不能用普通查询后无条件 UPDATE 替代。populate_existing 防止 Session 身份映射里的旧值掩盖数据库新值；no_autoflush 避免查询刷新其他待写数据。服务在 try 外拒绝已有事务，避免错误回滚调用方工作，成功前复制普通结果，commit 成功才返回。

项目证据：test_workspace_binding.py 的两类并发测试使用 pg_blocking_pids 确认实际锁等待，验证后来的请求读取首个已提交目录。16 条绑定专项加相关测试共 84 passed；提交故障在真实 flush 之后注入，独立连接验证回滚和恢复。此处验证提交前明确失败，不证明连接中断后的提交结果可判定。重复请求会重新验证目录，目录被删时不能承诺仍成功。目录校验期间持有行锁，因此不能在此事务内加入递归扫描或模型调用。

## 绑定接口返回 500 是否说明绑定没有发生？

不能。事务可能已提交，随后在构造响应时发生错误。HTTP 边界要使用“结果未确认”，前端不能自动按未提交处理或任意换绑；重复同一规范路径仍经过校验。服务异常与请求校验应转换为稳定错误码，不能反射原始路径、SQL 或异常正文。

## 为什么选择目录要经过本地服务，取消请求又不等于撤销保存？

浏览器目录控件提供相对路径或目录句柄，不能直接充当 Python Runtime 的本机绝对路径。当前本地 Web 产品通过严格本地 POST 请求打开系统目录窗口，选中后校验并保存；原生调用使用固定参数、不插入用户命令，先校验资源归属、释放数据库连接，再等待用户选择，保存时重新检查行锁与归属。窗口取消是正常 204；网络中断或返回失败则可能发生在提交之后，页面显示结果未确认并通过 GET 回读，不能自动重复选择或覆盖目录。

证据：test_directory_picker.py、test_workspace_selection_api.py 与 directory-select-route.test.ts 覆盖平台输出、超时/忙碌、取消无写入、本地访问边界、等待期间 Session 关闭、并发绑定冲突和白名单响应。原先 HTTP/BFF/页面待接入的限制已由目录选择交互补齐；文件授权与 Sandbox 仍未实现。复习优先级高，参考答案已整理、尚未模拟。


## 为什么文件工具的根目录必须来自已授权任务，resolve 后还不能直接宣称安全读取？

复习优先级：高。参考答案已整理、尚未模拟。

模型只提供相对路径，服务端执行上下文提供身份和任务定位。先通过 owned_task 联查项目、任务与会话归属，再复制数据库中的绑定目录并关闭 Session；不存在或不可访问的任务不能触发文件系统探测。未绑定目录明确拒绝，不回退到 cwd。只读查询无需 commit，文件系统解析不能占着数据库事务等待。

工具协议统一用正斜杠；同时识别 POSIX 根路径、Windows 盘符/根路径/UNC，拒绝盘符相对路径 C:foo、所有 .. 段、反斜杠、替代数据流冒号及设备名。代价是部分 Unix 合法文件名不受支持，换取各平台一致的输入语义。PureWindowsPath 规则测试不等于 Windows 实机验收。

重新校验保存的规范根目录，检测它是否改为指向别处的链接；对目标 strict resolve 后按路径层级判断 is_relative_to，而不是字符串 startswith。项目内链接可用，链接到项目外与同名前缀兄弟目录均拒绝。不存在、断链、循环链接和权限异常采用稳定错误分类，不回传底层路径。

失败场景与限制：返回 Path 后，目录或目标仍可能被另一个进程替换。根目录规范字符串相同也不证明目录对象身份相同；本课没有持有目录/文件描述符，不提供原子检查加打开，也没有验证硬链接来源、挂载边界、可读性或文件内容。真正读取时必须另行设计打开阶段边界和资源限制，不能简单把 resolve + open 当成完整 Sandbox。

项目证据：apps/api/app/services/workspace/directory/workspace_path.py 与 apps/api/tests/workspace/directory/test_workspace_path.py，63 条专项通过；真实临时文件/目录/符号链接及隔离 PostgreSQL 验证授权先行、Session 关闭、仅 SELECT、无 commit 和数据库失败清理。权限与通用系统异常采用故障注入；未做 Windows 实机或文件读取竞态验收。此前章节中的“文件授权未实现”是阶段历史，本次已补路径解析授权，实际安全读取与 Sandbox 仍待实现。


## 为什么有界文本读取不能只用 resolve + read_text？

复习优先级：高。参考答案已整理、尚未模拟。

resolve只确定检查时刻的路径。当前受限读取从规范路径的根逐段使用dir_fd和O_NOFOLLOW打开目录，末端打开前stat、打开后fstat核对普通文件与设备/inode/大小/时间；O_NONBLOCK避免替换为FIFO后打开阻塞，ExitStack在所有分支关闭描述符。它防止规范路径打开时跟随新链接，但不等于完整文件系统隔离，也不阻止目录搬移或同一路径对象替换。

大小检查只是提前拒绝，实际读取仍须最多上限+1字节，避免文件增长后突破内存/输出预算；短读不代表EOF，空字节串才结束。严格UTF-8并拒绝NUL是明确接受策略，不是通用二进制鉴定；超限不返回部分结果。读取后比较元信息可发现常见变化，但不能声称有原子快照。普通文件非阻塞标记也不提供磁盘I/O硬超时。

项目证据：workspace_file.py与test_workspace_file.py，新增35条，与路径课63条共98条通过（1.69s）；真实替换与句柄跟踪、读取增长/缩小/同长度修改、边界大小及两条PostgreSQL授权集成。Windows缺少所需能力时拒绝，不回退普通open；未做Windows实机验证。历史“实际读取待实现”已由本课补齐，工具注册、完整Sandbox与快照仍未实现。


## 为什么工具上下文不可变仍不能替代执行时授权？

复习优先级：高。参考答案已整理、尚未模拟。

可信来源与不可变是不同问题：frozen dataclass防止正常字段赋值，不阻止不可信调用者构造对象。身份来自服务端认证，当前会话经Conversation→Task→Workspace联查，同时约束会话和项目所有者；工具模型参数不承载user_id、Task、Workspace或root_path。同用户多个项目也必须由当前会话推导范围，不能让模型自由挑选。

只复制普通标识并关闭Session，不持有ORM对象或跨模型等待的事务/锁；上下文可以在未绑定目录时构造，因为任务定位不等于文件能力。后续读取再查归属和绑定，避免把已过期快照当作永久访问许可。模式切换不能删除文件工具需要的所有权条件。

## 为什么工具注册、模型可见性与执行授权要分别处理？

复习优先级：高。参考答案已整理、尚未模拟。

注册表说明服务端有哪些实现；按上下文生成模型工具列表，只展示本次执行可用的能力；Runtime/execute的上下文守卫和读取服务的再次授权负责实际阻止越权。模型可能猜到未展示的工具名，所以隐藏Schema不能替代执行检查。每次生成独立列表及Schema，避免并发任务互相修改能力描述；上下文本身不进入模型消息。

已知文件故障转换成白名单SafeToolExecutionError，Runtime生成失败Observation，code沿用tool_execution_failed，details承载固定业务分类。不能返回含error的成功字符串，也不能反射底层异常正文；未知异常仍走通用安全失败，取消不吞掉。

## 命令参数数组与结果校验能否代替 Sandbox？

复习优先级：高。参考答案已整理、尚未模拟。

不能。argv数组保留参数边界，避免自行拼接命令字符串，但sh -c或解释器仍能执行任意代码；相对cwd仅为语法与定位输入，不限制进程访问范围。模型请求只提供argv和相对工作目录，身份、环境、超时与输出策略由服务端控制。后续还须实现执行授权、Sandbox和进程树停止证据。

结果要区分已退出、超时、取消与启动失败：非零退出可表示测试失败，不等于无法启动；POSIX信号退出可能为负值。启动失败必须有固定分类，不能同时声称存在退出码或进程输出。超时/取消状态本身不证明子进程已停止，执行器需先清理。原始输出按字节限制捕获，展示字符串按字符限制；不能先无限读取再用Pydantic拒绝。stdout/stderr分别记录截断，丢弃输出后仍需排空管道，避免子进程被管道阻塞。

显式清理补充：为什么删除要用完整ID且不能把超时当作失败未生效？删除前按原token/完整ID重新确认created身份，随后非强制rm只作用于该ID，避免名称被替换后误删新对象；核对删除回执并成功查询缺失后才返回完成快照。查询与删除非原子，仍有高权限并发修改边界；不强制删除或自动停止。删除超时可能已经生效，保留token/ID并报告清理未确认，不自动重试。已有目标不存在也不能靠通用inspect错误宣称幂等成功。sandbox_cleanup.py新增41条常规专项，直接相关共74条通过，另2条真实Docker验证正常删除、错ID拒绝、删除后响应丢失与重复请求无再次rm。参考答案已整理、尚未模拟；复习优先级高。

隔离配置复核补充：创建argv表达意图，inspect表达daemon返回的配置；对同一响应先核对执行身份，再核对HostConfig网络/权限/只读根/资源及挂载。MemorySwap是内存加swap总额，与正Memory相等才表示禁用swap；不能把bool/float或字符串当作整数限额。HostConfig.Tmpfs声明和顶层Mounts摘要需要同时检查，摘要空不能代替声明，禁止其他挂载入口及镜像匿名卷。测试218条纯校验及1条真实created容器通过，恶意变化只注入响应副本，临时容器已清理。范围只覆盖显式列出的策略，不证明内核已实施或消除检查后修改窗口；启动与停止生命周期仍待接。复习优先级高；参考答案已整理、尚未模拟。


### 只读根文件系统能代替 bind 挂载只读吗？

复习优先级：高。参考答案已整理、尚未模拟。

不能。根文件系统与 bind 挂载是独立边界：规格显式声明 readonly、rprivate、非递归；核对 HostConfig.Mounts 中 Type/Source/Target/ReadOnly/BindOptions 与顶层 Mounts 的 Type/Source/Destination/RW/Propagation，同时保留网络、权限、资源、WorkingDir、tmpfs 和匿名卷检查。不能从 inspect 读出来源再把它当作期望值，期望来源必须由服务端持有的样例确定。默认入口继续拒绝 bind，样例分支只允许唯一固定目标。

如何证明写入失败来自挂载？样例置于宿主 0700 私有父目录，挂载子目录允许容器访问；无敏感内容的探针文件设置 0666，实机要求读取成功且写入返回 EROFS，并核对 statvfs 只读标志。EACCES 只能说明普通权限不足，不能单独证明只读挂载。宿主字节/inode/mtime 不变是副作用证据，不能代替容器返回的退出事实。

失败场景：目录路径未变但 inode 已替换、任一路径段变为链接、错误源、额外挂载或重复目标都拒绝；同字段值的伪造样例对象也不能冒充本进程登记。来源检查与 Docker 操作不是原子事务，当前限定服务端自建且无外部写者的样例；没有消除恶意同 UID/高权限主体造成的 TOCTOU，也没有提供重启后的执行权。容器确认缺失前不能释放样例，连接失败不等于缺失，部分清理失败保留现场。

项目证据：`sandbox_sample.py`、`build_sample_sandbox_create_spec()`、`sandbox_isolation_policy.py`；自动测试见 `apps/api/tests/runtime/sandbox/test_sandbox_sample.py` 和 `test_sandbox_sample_probe.py`，实机入口见 `scripts/verify_sandbox_sample.py`。最新验收范围与未验证边界只维护在 [交接](../../../LEARNING_HANDOFF.md#最近验收摘要)。

### 为什么 Task 样例 ready 仍不能直接作为命令来源？

复习优先级：高。参考答案已整理、尚未模拟；本课由教练单课授权实现。

ready 是查询时的登记快照，不预留来源，也不证明当前会话仍属于原 Task。内部命令来源入口只接服务端身份与当前会话，从数据库关系推导 Workspace/Task；随后通过 TaskSampleBindings 独占借用、重新核对归属与绑定，并再次查询会话关系，拒绝两次查询间可观察的迁移。授权事务在使用来源前关闭，不持数据库锁等待文件操作。两次读取不是原子租约，无法检测 ABA 或阻止之后的外部写者。

正常退出只归还占用，不删除 Task 来源；异常/取消由底层保留目录、封锁登记，同时释放 busy。来源视图退出或进程变化后不能再读取路径，但无法撤销已复制的 Path，所以可信调用方仍必须保证后台使用不越过作用域。此来源视图不是公开授权凭证，也不直接执行 Docker；模型命令通过后续独立快照桥接。Task 样例 0700/0600 与 Sandbox 的 UID 10001 不能直接互用。现有桥接在借用内通过逐级无链接目录描述符读取固定 example.txt，检查根目录身份、文件类型/单链接/权限和读取前后版本，实际最多读取 256 KiB 加一个判超限字节。归还正常结束后才创建独立快照，不放宽原 Task 权限。快照文件 0444 不替代容器 readonly 挂载，原 EROFS 探针继续使用 0666。

所有权取舍：归还失败时尚无目标；复制失败时 Task 已归还，异常只携带目标部分现场且不登记成功。正常目标与 Task 独立，Task 后续改写/关闭不影响快照，未来容器未确认缺失时须保留目标而非继续借用 Task。字节保留 BOM/CRLF/非 UTF-8/NUL，不以文本解码或截断伪造完整快照；身份及 mtime/ctime 核对不保证恶意并发写入的原子一致性。证据：[来源读取](../../../apps/api/tests/runtime/command/test_task_command_source_read.py)、[快照工厂](../../../apps/api/tests/runtime/sandbox/test_sandbox_snapshot.py)、[PostgreSQL 桥接](../../../apps/api/tests/runtime/sandbox/test_task_sample_snapshot.py)。本次桥接核心由学习者参考实现，测试由教练补齐；参考答案已整理、尚未模拟。

证据：[可信来源借用专项](../../../apps/api/tests/runtime/command/test_task_command_source.py)，真实隔离 PostgreSQL 与临时目录，覆盖绑定/会话变化、独占、异常封锁和作用域失效。


Task 快照执行补充：`run_task_sample_command` 将独立快照交给共享 Sandbox 生命周期，原 Task 借用不会持续到容器退出。同步准备在工作线程运行，asyncio 取消无法停止线程；因此准备任务受 shield 保护，重复取消也先等待完成，收回完整快照或部分创建定位，再传播取消且不启动容器。只等待线程、不读取其结果会丢失资源所有权。准备尚未尝试 create 的恢复与“已知容器 ID”清理是不同边界，不能混用。

本课由教练按单课授权实现。证据：[编排与准备取消专项](../../../apps/api/tests/runtime/sandbox/test_task_sample_command.py)、[真实 PostgreSQL/Docker 专项](../../../scripts/verify_task_sample_command.py)。真实链路覆盖快照后原文件改写、读取/非零退出/超时/取消、create/rm 回执丢失与显式收尾。参考答案已整理、尚未模拟。


Task 快照恢复记录补充（复习优先级高，参考答案已整理、尚未模拟）：为什么要在准备前预留记录？准备线程本身就可能创建完整快照或部分现场，先执行再尝试记账会在容量不足时丢失资源所有权。新 journal 按服务端身份/会话限制内部使用，在纯策略校验后预留最多 16 条；参数转成 tuple，执行从记录构造新请求。成功保存命令 JSON，非零退出仍为 completed；异常/取消先同步保存完整恢复对象，再传播，二者之间没有 await。

关闭仅拒绝新预留，不中断在途工作、不清理目标、不丢弃记录；终态只允许从 pending 写入一次。恢复对象和命令结果均冻结，快照句柄须保留工厂登记的原对象，不能深复制成一个看似相等却无效的新句柄。容量满时拒绝，不按时间或终态自动淘汰尚需处置的资源。作用域匹配不是授权，真正执行仍经过 Task 借用；请求层仍持有 journal，现已新增独立 TaskSampleRecoveryStore 按服务端用户/会话/Run 保存作用域。证据：[43 个记录与编排组合用例](../../../apps/api/tests/runtime/sandbox/test_task_sample_command_journal.py)。


应用级作用域补充（复习优先级高，参考答案已整理、尚未模拟）：请求函数结束不代表资源消失，因此 store 保留 journal 与原快照句柄。获取同 Run 时必须匹配用户与会话，不能仅凭 Run ID 取得资源；同归属复用原对象，不替换已关闭 journal 来绕过预算。关闭作用域要求本 store 持有的原对象，并只封闭新预留；已预留执行仍可补齐终态。每应用最多 32 个作用域，不自动淘汰未知或已完成记录，容量满保守拒绝。

FastAPI lifespan 独立建立 store，退出时封闭登记、释放 app.state 引用，不调用 Docker/文件清理；单进程内存所有权不等于持久恢复，旧引用存在也不能承诺重启找回资源。归属元组用于防内部错配，真正业务权限仍需数据库重新授权。证据：[作用域组合测试](../../../apps/api/tests/runtime/execution/test_task_sample_recovery_store.py)、[应用生命周期](../../../apps/api/tests/runtime/execution/test_task_sample_store_lifespan.py)。


内部工具适配补充（复习优先级高，参考答案已整理、尚未模拟）：工具输出与恢复记录必须分开。成功只序列化现有 CommandResult，非零退出仍返回真实结果；succeeded 为内部计算属性，不额外改写 JSON 契约。身份、会话、Run、store 和绑定服务由冻结内部上下文注入，不进入 CommandRequest Schema。模型参数只描述命令，不能选择宿主目录或资源归属。

失败映射依据阶段事实：准备可能留下部分目标，不能说“无副作用、可重试”；有 command 的清理失败不能冒称命令未执行；无证据异常保持结果未知。新适配的 SafeToolExecutionError 不附带 recovery，仅固定 code/message 可进入公开输出，完整证据已在底层 journal 保存。取消保持取消语义，输出投影失败也不能覆盖已保存的 completed。命令 stdout/stderr 是正文，本层不提供任意内容脱敏保证。证据：[35 个适配组合用例](../../../apps/api/tests/tools/test_task_sample_command_tool.py)。


请求级注册补充（复习优先级高，参考答案已整理、尚未模拟）：能力展示是请求快照，不能把 ready 当作执行许可。本地聊天 ready 绑定 Task 快照执行器，missing 绑定普通无挂载执行器，busy/sealed 不提供命令能力；查询失败不降级。模型与 Runtime 使用同一工具定义，身份、Run 和 store 均由服务端注入，模型 Schema 不变。

为什么执行前再查一次还不够？会话可能在复核后、借用前改绑 Task；必须把请求原上下文传到实际借用入口比较，借用中的原有二次核对也保留。占用变化、迁移或读取失败拒绝执行，不静默换成普通命令。作用域首次执行才分配，请求结束先拒绝新调用，流关闭抛错也在 finally 封闭并保留 journal；关闭不是清理或删除恢复证据。

证据：[请求装配与关闭竞争 16 例](../../../apps/api/tests/tools/test_request_task_sample_tools.py)、[真实 PostgreSQL 聊天路由集成 5 例](../../../apps/api/tests/chat/test_task_sample_chat_integration.py)。集成验证 NDJSON、Run/事件持久化及复核后迁移拒绝，模型与 Docker 为受控替身；不等于浏览器、HTTP 传输或真实 Docker 联合验收。

### 为什么命令失败后不能无条件删除样例目录？

复习优先级：高。参考答案已整理、尚未模拟。本次编排由教练按单课授权实现，不代表学习者已独立掌握。

文件系统与 Docker 没有共同事务。create 响应丢失时，daemon 可能已经创建容器但调用方没有 ID；取消或 CLI 退出也不证明容器已停止。样例拥有者必须保留 token、已知完整 ID、请求快照、来源句柄及各阶段已确认事实，不能在 finally 无条件释放仍可能被容器使用的来源，也不能盲目重试 create。

正常路径先完成 attach 排空与退出核对，再重读归属和 exited/Pid=0，按完整 ID 非强制删除、成功查询缺失，最后清理样例。非零退出也有完整命令事实，可以正常释放资源；反过来，输出成功但删除失败，应保留 command 和“清理未确认”，不能把命令改成未执行。停止确认、删除尝试、缺失确认、样例清理是不同证据。异常路径只完成执行器拥有的连接/读取与必要停止收尾，后续恢复需再次授权；创建前验证、attach 前验证和启动前验证分别覆盖不同等待窗口。

样例工厂中途失败也要保存独占创建后的现场位置；mkdir 名称碰撞不能认领旧目录。进程内记录不是持久 checkpoint，旧快照不能授予新的执行或删除权。当前实现以调用方保存恢复信息换取不盲目回滚的保守策略，代价是失败后可能保留资源；已有内部只读诊断及显式清理。显式清理先校验完整登记来源，再按完整 ID 重核容器归属及 created/exited 状态，非强制删除并成功查询缺失后才释放来源；运行中不自动停止，未知 ID 不按名称接管。删除回执丢失或取消保留来源与 delete_attempted，拥有者再次明确调用仍须重新查询，不能信任旧 absent 标志。文件清理失败保留已确认的容器缺失事实；部分来源现场拒绝盲重试。

取舍：清理入口只供原内部拥有者使用，要求一个样例仅供原命令使用且没有并发执行/外部写者；恢复对象不是公开授权凭据。同事件循环清理互斥只防重复调用，不是跨进程租约。容器不存在也不证明任意其他容器没有使用该来源，故不支持将来源转借或复制记录接管资源。证据：[显式清理专项](../../../apps/api/tests/runtime/sandbox/test_sandbox_sample_cleanup.py)、[真实 Docker 六场景](../../../scripts/verify_sandbox_sample_cleanup.py)。参考答案已整理、尚未模拟。

证据：`sandbox_sample_command.py`、`test_sandbox_sample_command.py`、`test_sandbox_sample_execution.py` 与 `scripts/verify_sandbox_sample_command.py`。实机通过 attach 读取/双路截断/非零退出/超时/取消；创建和启动响应丢失在真实操作成功后本地注入，不冒称实际断网。


### 为什么失败恢复诊断需要分别报告容器与来源状态？

复习优先级：高。参考答案已整理、尚未模拟。本课由教练单课授权实现，不标记独立掌握。

文件系统和 Docker 的读取不在同一事务中：容器可查但来源不可读，或者来源身份匹配但 daemon 不可达。分侧报告能保留已取得的事实，又不把异常降级成“资源不存在”或“可以重试”。身份匹配只说明目录/文件身份与结构符合记录，不是文件内容快照；它也没有重验运行中容器的完整隔离策略，不能作为执行或删除权限。

已知完整 ID 只按该 ID 查询，哪怕同名容器已重建也不能接管。未知 ID 可从原名称发现 created 候选，但须核对完整身份后按 ID 复核；正在运行或已经退出的同名目标不能凭名称认领。成功列举确认的 absent 不等于历史删除成功，更不补造命令退出结果。旧 stop_confirmed/container_absent 与当前观察分开保存，不改原恢复记录。

来源路径明确不存在才报 missing；链接/身份/声明结构变化报 identity_changed；权限或未知读取故障报 unconfirmed。没有本进程登记的对象报 unregistered，不凭原始路径探测宿主目录。取消继续抛出取消异常并保留恢复上下文，不返回一份看似完整的“未知”结果冒充成功查询。

证据：`sandbox_sample_reconciliation.py`、`observe_sandbox_sample()`、`test_sandbox_sample_reconciliation.py` 和 `scripts/verify_sandbox_sample_reconciliation.py`；实机比较每个只读观察区间的文件元数据/字节、登记及容器状态/配置不变，同名重建也保持旧 ID 边界。权限/daemon 读取失败用本地注入验证，不能声称真实网络故障已验收。

## 为什么文本替换预览要分离完整新内容与审阅Diff？

复习优先级：高。参考答案已整理、尚未模拟。

精确替换先验证旧文本非空且唯一命中；第二次find从首次位置+1开始，以拒绝aaa中aa这样的重叠歧义。不能用默认非重叠count判断唯一，也不能模糊匹配或自动选首处。256KiB输入/输出和4000行约束Diff计算规模，16384字符只限制展示；截断Diff不代表完整修改，不能据其完成审批。updated_content必须独立完整保留。

保留CR、LF、CRLF与EOF事实；审阅表示使用每行JSON转义，避免换行差异被隐藏，因此不是可直接git apply的补丁。预览不等于写入，原文内容基线、授权复核、审批和并发冲突仍须后续实现。规模限制不是硬CPU超时。

统一 Diff 解析补充（复习优先级高，参考答案已整理、尚未模拟）：为什么不能只校验旧行号？前一块增删会改变后续新位置，必须同时验证旧原文切片和新内容累计位置。零行范围表示行间间隙，转换零基索引时不能按普通起点减一；重复插入同一位置要求合并，拒绝重叠、倒序和模糊偏移。

无末尾换行标记作用于紧邻数据行，不计入行数；不能把无换行新行与后续未修改内容直接拼接。失败时不能返回已经应用前几块的部分候选，全部匹配和输出预算通过才构造结果。补丁、原文、候选及块数分别有界，字符数限制不替代 UTF-8 字节数。首版明确拒绝 CRLF、Git 扩展头、文件新增/删除和多文件；这是严格子集，不声称兼容任意 git diff。路径语法与候选内容都不代表业务授权或写入许可。

### 文件修改提案为什么分两段事务，为什么保存前仍需授权？（2026-09-21）

复习优先级：高。参考答案已整理、尚未模拟。

参考答案：先查询归属并复制内部Task/Workspace编号和绑定目录，关闭Session后读取文件和计算Diff；耗时I/O不占用数据库行锁。保存时新建写事务，按Workspace→Task→Conversation锁序重新检查当前归属，再比对身份和绑定，插入pending提案。仓库只flush，事务由服务提交，成功退出事务后才返回结果；与删除使用相同锁序，Task外键CASCADE使已提交提案随任务删除。

失败场景与取舍：预览期间项目/会话归属或绑定改变、任务被删均不能沿用旧授权；flush成功但commit前失败仍须回滚，不返回成功。文件系统不参与数据库事务，保存提案不能承诺文件基线仍有效，应用前必须重新检查。完整proposed_content单独保存，diff_truncated只描述审阅展示；pending与摘要均不是批准凭据。当前无请求幂等，重复调用会新建提案，提交响应不确定时不能盲目重试。当前无更新入口，并非数据库层强制不可变。

项目证据：test_file_edit_proposal_service.py与test_file_edit_proposal_migration.py共37条，相关共109条分批通过；含真实PG约束/迁移往返、双向行锁竞争、故障回滚、删除级联、外部编辑不覆盖。开发库升级后旧业务数据逐行一致。尚无提案HTTP/工具入口和实际文件写入。


补丁共用存储补充（2026-09-24，高优先级）：为什么不为补丁另建提案表或事务？两种输入都先生成授权的完整候选，再共享 pending 状态、双摘要、Diff、锁序与提交边界；复用应发生在保存流程，不能允许模型绕过预览提交任意候选。保存前仍重新授权与复核绑定；文件系统不参与数据库事务，外部编辑不会被覆盖，也不意味着保存的基线仍有效。绑定字符串复核不能检测变更后又恢复的 ABA 竞态。

[补丁提案专项](../../../apps/api/tests/workspace/proposals/test_file_patch_proposal_service.py)21例及原保存服务18例通过。after_commit 事件注入异常后，独立查询仍看到1条记录，说明调用失败不等于未提交；提交前异常则0条，两个场景均不返回成功或自动重试。该注入验证提交后异常语义，不冒称真实网络故障；当前没有请求幂等。测试还验证完整候选、截断 Diff、双摘要、授权查询兼容、并发变更拒绝和文件不变。参考答案已整理、尚未模拟。

提案查询补充（2026-09-21）：为什么不能仅凭proposal_id查记录？随机编号只提供定位，查询应同时约束Task/Workspace编号和Workspace、Conversation的用户归属，并通过实际外键连接提案；不存在/无权访问返回相同安全错误。单条SELECT使授权与结果使用同一语句快照，但不是后续应用的授权凭证。显式投影公开列避免加载bound_root/proposed_content，冻结普通结果避免Session关闭后的隐式查询。Diff仍包含编辑片段，不能宣称内容完全脱敏。文件删除或解绑后可查询历史提案，应用时仍须重新授权、复核绑定和内容基线。test_file_edit_proposal_query.py新增15条，相关33条通过，真实PG验证跨用户/项目/任务/会话边界与只读事务。复习优先级高，参考答案已整理、尚未模拟。

## 文件修改提案的并发审批（2026-09-22）

复习优先级：高。参考答案已整理、尚未模拟。

**问题：两个请求同时批准和拒绝同一提案，怎样避免后提交者覆盖？为什么批准后还不能直接写文件？**

参考答案：为每次决策创建独立事务，按Workspace→Task→Conversation→Proposal固定顺序取得行锁并重新检查归属。在锁内读取最新状态，仅允许pending转换为approved/rejected；终态重复提交或反向提交都返回冲突。成功结果必须等事务提交后返回，flush只验证SQL与约束。未知提交结果不自动重试，应查询已持久化状态。数据库CHECK约束限制状态集合并禁止approved与截断Diff组合，但不替代服务端的合法转换检查。

批准只记录对保存内容的决策。批准时检查目录绑定相同且Diff完整，仍不能证明当前文件未被外部编辑，也不能证明同一路径仍指向同一目录对象。实际应用必须再授权并验证基线；本课完全不读写文件。拒绝可关闭目录已解绑或Diff截断的提案。创建回执保留创建时pending，详情显示查询时状态，不能把历史回执伪装成当前状态。

失败场景与取舍：先读pending再加锁会让竞争请求使用旧判断；加锁后重新读取避免覆盖。统一锁序与删除流程兼容；目前项目级锁也会串行化同项目其他提案，优先保证边界清晰，尚未优化锁粒度。状态列没有审批人/时间或变更历史，不能声称完整审计。降级只允许全部pending；存在决策时拒绝，不能静默抹掉用户决策。

应用占用补充（2026-09-22，优先级高，参考答案已整理、尚未模拟）：审批状态与应用状态为何分开？approved只是用户决定；idle→running表示某次执行已持久领取，只有事务成功返回令牌后才能进入未来执行器。running→applied/not_applied/uncertain通过重新授权和令牌匹配完成；所有已领取状态均不能再次领取，not_applied也不自动重试。随机令牌隔离迟到执行结果，但不是权限凭据，Workspace/Task/Conversation归属仍需核对。

### Git状态为什么不能按行解析或把空输出当干净仓库？（2026-09-24）

pack与PC补充（高优先级；参考答案已整理、尚未模拟）：磁盘pack应自包含，REF_DELTA按对象ID找基对象，OFS_DELTA按当前位置的反向偏移找基对象；增量的目标长度、复制范围、指令和链深度都须限制。完整包校验和不能替代对象内容哈希；idx不是授权证据。本实现直接有界解码pack并重建对象哈希，保留文件观察作用域以复核变化。引用不存在与pack尚未查询的状态不可混淆。PC按需先取绑定修订再查询，后端再次授权，BFF还要校验回执资源并限制响应正文；取消或失败不保留旧差异。证据：[pack解析](../../../apps/api/app/services/workspace/git/pack_objects.py)、[作用域读取](../../../apps/api/app/services/workspace/git/object_store.py)、[BFF测试](../../../apps/web/test/features/workspaces/staged-route.test.ts)、[PC验收](../../../apps/web/test/browser/staged.mjs)。格式依据：[Git pack格式](https://git-scm.com/docs/gitformat-pack)。

暂存API补充（高优先级；参考答案已整理、尚未模拟）：为什么不能直接序列化只读观察dataclass？内部来源含宿主路径、主键和配置，repr隐藏不等于JSON隐藏。公开层显式构造字段白名单，只返回资源/修订/固定状态与有界差异；按最终UTF-8 JSON字节计费，超限整次拒绝而非截断成伪完整列表。身份由本地可信依赖提供，客户端修订不能替代授权；重复和未知查询参数拒绝。已知变化映射409，保守格式/预算拒绝422，未知错误固定500且不反射底层文本，所有结果no-store。项目观察不写业务表，但已有身份依赖执行用户幂等初始化，不能宣称全HTTP链只有SELECT。测试装配也须包含生产本地中间件，单独路由和身份依赖不足以复现生产403边界。证据：[API契约](../../../docs/project-staged-api.md)、[29项隔离API专项](../../../apps/api/tests/workspace/git/test_staged_api.py)。

暂存联合观察补充（高优先级；参考答案已整理、尚未模拟）：如何避免HEAD与index各自读取成功却来自不同观察轮次？在内部HEAD图观察器尚未退出时，用它的.git目录描述符读取index，比较后仍不立即返回；第二次授权及两侧全部文件退出复核通过后，再构造共用来源的结果。纯比较只能说明两个输入的关系，不能替代这个组合边界。None与空tuple分别表示无法比较和已比较无差异，多个缺失原因可同时保留；树缺失、解析损坏、权限失败不能被降级成空结果。未诞生HEAD在当前策略中仍不自行补成空树。这个结果不等于跨数据库/文件系统原子快照，也不证明工作树干净。下一层公开响应还必须白名单投影与字节预算，内部dataclass里的来源根路径等不能直接序列化。证据：[组合观察](../../../apps/api/app/services/workspace/git/project_staged.py)、[29项隔离专项](../../../apps/api/tests/workspace/git/test_project_staged.py)。

暂存比较补充（高优先级；参考答案已整理、尚未模拟）：为什么同一对象ID仍可能是暂存修改？内容ID相同但文件模式变化也需要报告；缓存stat和mtime不能代替对象与模式比较。stage1/2/3是冲突版本，存在任一冲突stage都报告unmerged，只保留真实存在的stage，不能用HEAD或stage0填补缺失一侧。文件目录替换按各路径新增/删除呈现；相同内容从旧名到新名仍是删除+新增，重命名属于额外推断。输入按原始UTF-8路径和stage校验顺序、重复及同stage前缀冲突，不折叠大小写；跨stage目录文件冲突可保留。即使类型冻结也不证明对象来自解析器，因此重新检查实际比较字段并限制两侧条目与路径预算；快照摘要与cached stat不参与比较也不在此重新认证。空差异仅说明传入投影相等，不证明快照同源或工作树干净；缺失输入必须拒绝，后续还需同作用域授权读取。证据：[纯比较器](../../../apps/api/app/services/workspace/git/staged_compare.py)、[57项专项](../../../apps/api/tests/workspace/git/test_staged_compare.py)。

tree图补充（高优先级；参考答案已整理、尚未模拟）：为什么对象去重不能代替递归预算和循环检测？多个目录可引用同一个合法子tree，缓存按对象ID避免重复读取，但每个路径仍需展开；若只计唯一对象，少量对象可产生大量输出。分别约束唯一对象/保留描述符、压缩与解压总量、深度、访问次数、叶数以及单路径/累计路径字节。祖先集合拒绝回边，全局已见对象不能当循环，因为共享子树合法。全部文件观察器保持到第二次授权后统一复核，代价是资源保留，因此对象数也限制描述符。解压全局预算在缓存前检查，单次瞬时解析仍受独立1MiB上限；不能把缓存预算冒充进程总内存上限。任一后续子tree缺失/损坏/变化都不返回已收集叶条目；空目录无叶输出，完整空图不同于未取得前置commit。仅目录递归，链接/gitlink不跟随，blob未读，所以叶引用存在性仍未知。证据：[图观察](../../../apps/api/app/services/workspace/git/tree_graph.py)、[30项专项](../../../apps/api/tests/workspace/git/test_tree_graph.py)，循环分支为注入结果测试，非真实哈希循环对象。

根tree观察补充（高优先级；参考答案已整理、尚未模拟）：为什么不能先调用公开commit读取，再按返回的tree_id另开一次读取？两次分别通过的检查可能来自不同绑定或HEAD时刻，不能合称同一次观察。根tree入口嵌套内部commit观察器，使config、HEAD、引用和commit描述符保持存活，再打开根tree；第二次授权之后逆序复核字节/身份并释放，全部退出成功才返回聚合结果。无HEAD对象、commit缺失、tree缺失分别保留；后两者都注明pack未查，不能宣称对象不存在。成功空树有完整已校验对象，缺失则没有。文件I/O在两个短只读事务之外，避免长事务；代价是没有跨数据库与文件系统的原子快照，不能消除所有ABA或返回后的修改。读取根tree也不证明子tree/blob存在或类型正确，不等于完整HEAD快照。证据：[根tree观察](../../../apps/api/app/services/workspace/git/project_tree.py)、[29项隔离专项](../../../apps/api/tests/workspace/git/test_project_tree.py)。

loose tree补充（高优先级；参考答案已整理、尚未模拟）：tree条目为什么不能按NUL整体拆分、也不能只按名称文本排序？名称后的对象ID是固定20字节二进制，可包含NUL；必须先读取规范模式、名称终止符，再消耗完整ID。Git按原始名称字节排序，目录比较时带虚拟末尾斜杠，所以a.c排在目录a前。文件a与目录a可被a.c隔开，仅检查相邻重复会漏掉冲突，需集合检查全部名称。封装先限制压缩/解压字节，要求zlib流完整且无尾随或拼接数据，再核对tree正文长度与完整对象SHA-1；条目、名称同样有预算。首版仅规范模式和严格UTF-8保守名称，拒绝非规范或不支持输入而不自动修复；代价是不能覆盖所有Git树。空树是合法完整对象，缺失或读取失败不是空树。哈希与条目验证不证明子对象存在或类型正确，更不是路径访问授权。证据：[纯解析器](../../../apps/api/app/services/workspace/git/loose_tree.py)、[94项专项](../../../apps/api/tests/workspace/git/test_loose_tree.py)；依据：[Git对象封装](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects)、[条目读取](https://github.com/git/git/blob/master/tree-walk.c)、[排序实现](https://github.com/git/git/blob/master/tree.c)。

index授权读取补充（高优先级；参考答案已整理、尚未模拟）：为什么解析成功还不能直接交付index结果？解析只说明传入字节符合子集，不能证明请求者仍拥有项目或文件路径仍指向这些字节。读取入口先联表授权与绑定修订核对，在活跃config/.git描述符内有界读取，再做第二次授权，退出时复核命名对象身份和重读字节。数据库只执行两个短只读事务，文件I/O不占用事务。缺失、合法空索引、读取未知是三种不同情况：只有完整合法index可返回空entries；权限错误不能冒充缺失，缺失观察结束前新建文件也须拒绝。已读文件同字节替换、修改/删除、config变化、权限归属变化及二次读取失败均不能交付旧结果。固定解析错误码保留，底层路径和异常不回显；异常和中断关闭描述符。取舍是额外读取及严格兼容子集；前后复核仍不是跨资源原子快照，不能排除所有ABA，更不能证明工作树干净或授予执行权。证据：[授权读取](../../../apps/api/app/services/workspace/git/project_index.py)、[31项隔离专项](../../../apps/api/tests/workspace/git/test_project_index.py)。

index v2补充（高优先级；参考答案已整理、尚未模拟）：为什么二进制索引不能只按条目数解包后直接使用？必须同时核对DIRC、版本、网络字节序、文件预算、末尾SHA-1、每条固定字段/路径长度与NUL填充；对齐相对于条目起点，路径长度字段达到4095时是哨兵而非实际长度。顺序以原始路径字节再按stage比较，不能用本地语言排序。相同路径可有缺少某一侧的merge stage，但不能重复或同时出现stage0；跨stage目录文件冲突可表示，不能一概当作损坏。同stage的目录文件冲突应拒绝。首版只支持无扩展SHA-1/v2，TREE等可选扩展也拒绝，代价是许多普通Git索引暂不兼容；不能忽略split/sparse等语义后继续访问文件。校验和只核对这些字节，缓存stat不是实时文件状态，模式/路径不给予访问权，也不证明对象存在或仓库干净。空输入与带完整头和校验和的合法空索引必须分开。证据：[纯解析器](../../../apps/api/app/services/workspace/git/index_v2.py)、[81项专项](../../../apps/api/tests/workspace/git/test_index_v2.py)；依据：[官方index格式](https://git-scm.com/docs/index-format)。


loose对象补充（高优先级；参考答案已整理、尚未模拟）：为什么压缩字节少、哈希匹配或文件存在都不足以验证HEAD提交？少量压缩输入可以产生大量输出，应分别限制256KiB输入与1MiB解压结果，使用带最大输出长度的zlib解压，不以无界flush补尾；必须确认EOF且没有尾随或拼接流。SHA-1核对包含对象类型/声明字节数/NUL及正文，随后仍检查声明长度和支持的commit正文结构；哈希只是对象命名约定，不是签名或权限。当前只支持UTF-8简单commit、16KiB头部和最多16个parent，签名/encoding等扩展暂拒绝。解析得到tree/parent ID不证明这些对象存在，更不能推出完整仓库有效。缺失loose文件可能因为对象在pack中，结果明确标记pack未查；unborn候选不创建虚构对象。服务在本次授权与活跃元数据描述符内按ID构造路径读取，返回前复核字节/身份并释放。证据：[校验服务](../../../apps/api/app/services/workspace/git/loose_commit.py)、[45项专项](../../../apps/api/tests/workspace/git/test_loose_commit.py)；依据：[Git对象格式](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects)。


packed-refs补充（高优先级；参考答案已整理、尚未模拟）：loose与packed记录冲突时谁优先？loose为当前值，只有loose缺失才使用packed；不能把损坏loose视为缺失回退。当前观察器同时保留两种来源并完整校验packed，损坏尾部即使不影响本次查找也拒绝。已知头部特征不是内容正确性的证据：声明sorted必须实际有序，未声明可无序；重复引用、前缀冲突、未知特征、孤立/重复peeled行均拒绝。peeled值只保留为声明，不替代主记录ID，也不证明对象类型。预算为256KiB/2000条/每行1100字节，ASCII/SHA-1子集、非空文件必须以LF结束；失败不能返回部分列表或“未诞生”。缺失packed在授权后复核仍缺失，存在时复核字节/身份，避免观察期间创建/替换后继续使用旧结果；仍非原子快照。代价是保守检查可拒绝Git更宽的合法格式。证据：[解析器](../../../apps/api/app/services/workspace/git/packed_refs.py)、[54项专项](../../../apps/api/tests/workspace/git/test_packed_refs.py)；格式依据：[Git packed后端](https://github.com/git/git/blob/master/refs/packed-backend.c)。


HEAD与引用补充（高优先级；参考答案已整理、尚未模拟）：为什么loose分支文件缺失不能直接表示未诞生分支？Git也可在packed-refs保存分支；当前packed-refs已按明确子集完整有界解析；只有同次观察中loose路径缺失且packed没有对应引用才返回unborn_candidate，仍不证明仓库内容完整或为空。HEAD支持固定refs/heads路径或40位非零小写SHA-1；路径限定ASCII子集/16段、每文件1024字节，拒绝上级路径、控制字符、链接、符号引用链与未知格式。引用解析出ID不等于对应对象存在，更不等于对象是提交。读取仍在本次授权与config/布局描述符内完成，授权后复核HEAD、引用字节和目录身份；缺失路径也复查，防止检查间隙创建后继续返回缺失。配置观察器仅内部提供活跃描述符，公开结果不携带可复用句柄。代价是SHA-256、Unicode及更宽Git引用语法尚不支持。证据：[HEAD服务](../../../apps/api/app/services/workspace/git/project_head.py)、[60项专项](../../../apps/api/tests/workspace/git/test_project_head.py)；依据：[Git引用规则](https://git-scm.com/docs/git-check-ref-format)、[HEAD与packed-refs布局](https://git-scm.com/docs/gitrepository-layout)。


配置审查补充（高优先级；参考答案已整理、尚未模拟）：为什么采用保守子集，而不是直接调用git config解析用户配置？原生配置包含include、条件include及可影响外部程序/路径的设置；本课不能通过运行不可信配置来证明它可信。首版严格UTF-8、16KiB/128个LF分段/单行1024字节，仅支持单core节和有限固定值，未知或复杂语义拒绝，不忽略。代价是remote/branch/user、CRLF、引号等合法配置也不兼容，必须明确显示为未支持而非宣称用户仓库非法。读取在重新授权的根和.git描述符作用域内完成，config无跟随/非阻塞打开后核对普通文件身份；前后元数据检查及授权后重读字节可发现观察到的变化，不能保证跨资源原子性或返回后不变。只返回固定键值和摘要，读取失败/超预算不生成部分成功。配置通过仍不验证HEAD/引用/index/对象，也不授予执行权。证据：[配置服务](../../../apps/api/app/services/workspace/git/project_config.py)、[43项专项](../../../apps/api/tests/workspace/git/test_project_config.py)；[Git配置语法依据](https://git-scm.com/docs/git-config)。

Diff请求闭环补充（2026-09-28，高优先级；参考答案已整理、尚未模拟）：同一个工具定义保留schema、描述、超时和参数模型，只在请求装配时包装执行器；必须使用原context对象，执行前重载会话归属，底层Task服务再授权。管理器属于应用，不全局共享；能力已展示也可能在执行前失效。超时/取消结束等待不代表同步Git线程结束，仍由ExecutionThreads追踪并等待收尾，不能提前释放请求资源。证据：[注册专项](../../../apps/api/tests/tools/test_git_diff_registration.py)覆盖跨应用隔离、上下文/关闭/授权失效、线程及超时取消；[聊天专项](../../../apps/api/tests/chat/test_git_diff_chat.py)经受控模型、真实临时Git与隔离PostgreSQL核对结果正文和终态持久化，最终助手回复仅一条。不是供应商模型或PC页面验收，教练按授权实现。

同步Git执行复用Runtime受跟踪线程，超时/取消只是等待结束，不能提前释放请求占用或把空结果当成功。失败只回灌固定Observation，参数校验错误不回显input。证据：[请求注册19例](../../../apps/api/tests/tools/test_git_status_registration.py)、[隔离数据库与真实Git聊天4例](../../../apps/api/tests/chat/test_git_status_chat.py)，覆盖上下文变化、关闭、线程收尾、模型往返及事件持久化；PC受控闭环已验证，真实模型措辞仍未验证。参考答案已整理、尚未模拟。

PC证据补充（2026-09-24，高优先级）：Run完成为什么不能推导工具成功？Agent可以消费失败Observation后解释失败并正常结束；四场景中缺失登记/配置变化两轮Run同为done，但只有TOOL_CALL_ERROR，界面须展示失败而非空成功。历史页的开始/结束事件会重复出现工具名，不等于重复调用；用POST次数、持久TOOL_CALL_START数量及原文件证据独立判断重放。[PC专项](../../../apps/web/test/browser/git-status.mjs)四场景、两种桌面宽度及刷新历史通过，[服务端夹具](../../../apps/web/test/browser/git_status_model.py)确认文件/项目绑定未变、未自动登记和生命周期清理。结果仍为通用JSON，样例来源可见；受控模型的正确措辞不能替代真实模型验收。参考答案已整理、尚未模拟。

## 多文件变更怎样在数据库与文件系统之间恢复？

复习优先级：高。参考答案已整理、尚未模拟。

数据库事务不能回滚文件系统。先保存 running 状态和持久 journal，再准备完整候选并保存其身份，随后把原 inode 移入私有恢复目录并发布新文件；终态必须以真实文件核对为依据。普通异常可尝试整组恢复，进程中断后必须从持久现场显式恢复，不能重新执行原应用。恢复前检查整组内容与身份；外部编辑、删除或未知现场保留 uncertain，避免用备份覆盖用户的新内容。它提供恢复协议，不提供跨文件原子可见性。

目录锁使用 PostgreSQL 会话锁，连接 autocommit，使锁覆盖文件 I/O 而没有长数据库事务。旧单文件入口使用同键非阻塞事务锁，避免持资源行锁等待目录锁形成死锁。锁仅串行化内部请求，外部写者仍需要基线与写后检查。

项目证据：`tests/workspace/proposals/test_change_sets.py` 覆盖四类操作、多个故障点、中断现场、并发、外部变化与恢复；协议见[普通项目执行](../../../docs/project-execution.md)。

## 隔离副本导出为何还要基线校验与事务回执？

复习优先级：高。参考答案已整理、尚未模拟。

副本隔离了工作过程，但不说明原项目此后没有变化。导出比较副本初始内容与当前内容，再检查原项目对应目标仍匹配初始基线，只创建待审批变更组。候选与 exported_id 同事务保存，响应丢失后查询返回同一候选，不能重复生成或直接写回。源任务和副本任务都重新授权，绑定修订和目录身份变化也必须拒绝。证据：`test_owned_areas.py` 与 PC `week5-completion.mjs`。当前内容副本不声称具备 Git worktree 的分支语义。
