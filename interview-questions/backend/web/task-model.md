# Task、Conversation 和 AgentRun 为什么分开建模？

复习优先级：高。参考答案已整理、尚未模拟。

Task 表达项目中的持续目标，Conversation 承载多轮交流，AgentRun 描述某一轮执行。一个 Workspace 有多个 Task，当前一个 Task 至多对应一个 Conversation，会话可有多个 Run。不能把最后一次 Run 的终态直接等同于任务整体完成。

## 旧数据与约束

Conversation.task_id 可空，让旧会话继续运行，不猜测归属或批量回填。PostgreSQL 普通唯一索引允许多个 NULL，但同一个非空 Task 标识只能关联一个会话。relationship 提供对象导航，数据库外键和唯一索引负责实际约束；back_populates 必须在正确的类上成对。

Task 的所有者沿 Workspace.user_id 查找；会话现有 user_id 仍保留。外键不能保证这两个所有者相同，未来创建服务必须先授权并在同一事务中创建 Task/Conversation。当前尚未实现此服务，不宣称关联约束已替代访问控制。

## 迁移故障与项目证据

create_all 可以创建新表，不能更新已有表，也不更新 Alembic 版本账本。开发库曾出现 Task 表已创建但会话列缺失的部分状态。只有核对版本、完整结构与表无数据并隔离演练后，才在一个事务中修复空表、执行真实迁移、比对目标结构并更新账本；不能直接 stamp 跳过缺失结构。

证据：test_task_model.py、test_task_migration.py；相关专项 41 passed，覆盖旧数据、NULL/唯一/外键、ORM 提交重读、真实升级回退及空表修复。开发库 f16a53d928bc，alembic check 无差异。Task 创建、恢复、删除及任务权限服务仍待实现。


## 如何避免只创建任务、没有创建会话的半成品？

创建服务拥有一个独立事务，先校验并锁定本人 Workspace，再创建 Task 与 Conversation，通过 ORM 关系安排插入顺序。会话 user_id 取自授权后的项目；flush 后复制普通结果，commit 成功才返回。会话插入、结果构造或提交前失败均整体 rollback；已有调用方事务必须在 try 外拒绝，避免误回滚别人的工作。事务内不等待模型、目录选择或外部调用。

证据：test_task_service.py 新增 25 条，相关回归共 46 passed。真实 PostgreSQL 验证 Task INSERT 已发生后，会话阶段 SQL 失败仍无残留；独立连接确认提交，过期配置开启时不重开事务，调用方未提交工作仍可自行提交。Task 创建服务已完成，HTTP/BFF/UI 仍待接入。重复调用创建不同任务，尚无请求幂等；模拟提交前异常不能证明提交成功后网络断开的结果可判定。复习优先级高，参考答案已整理、尚未模拟。


## Task 创建接口返回 500 为什么可能仍有两条已保存记录？

事务提交和 HTTP 成功响应不是同一个原子操作。服务提交后，响应构造或框架 response_model 校验仍可能失败。接口应返回固定 task_creation_uncertain 和安全提示，不说一定未创建；客户端在尚无幂等能力时不能自动重发。

证据：test_task_api.py 最终 33 条，分别注入提交后响应构造错误、结果字段错误和框架响应校验错误，验证身份/业务 Session 已关闭，500 不泄露原始信息，独立连接仍能查询到 Task 与 Conversation。此前“HTTP 待接入”的边界已完成；BFF/UI 和幂等恢复仍待实现。复习优先级高，参考答案已整理、尚未模拟。


Task 创建 BFF 补充证据：task-create-route.test.ts 59 条通过，校验请求项目与响应 workspace_id 一致、公开字段/错误白名单、来源与内部凭证、转发前后取消及正文阶段超时；没有自动重试。转发前取消可确认本次未提交，开始转发后无法据取消或错误断定事务未提交。BFF 已完成，上游为模拟，真实工作台集成与幂等恢复仍待接入。


## 禁用按钮能否保证创建请求幂等？

不能。ref 同步占位用于阻止 React 按钮更新前的连续提交；AbortController 和组件身份检查用于阻止旧项目响应修改当前 UI。这些都不能撤销已经提交的数据库事务。只有明确拒绝或明确未提交才恢复编辑；网络失败、未知响应或转发后超时应保留“结果未确认”，不能自动重发。成功后“创建另一任务”是新的用户操作。刷新或重新挂载会丢失当前表单的未知状态，服务端幂等和任务列表恢复仍需后续实现。

工作台集成证据：workspace-task.mjs 使用真实 BFF/API/隔离 PostgreSQL 验证创建、标题规范化和 Unicode 边界，并在上游返回 201 后主动丢弃响应，确认表单暂停提交、不重复发送。复习优先级高，参考答案已整理、尚未模拟。


## 首轮标题总结为什么不能放在数据库事务里等待？

模型响应延迟及失败不可控。先授权项目和任务、复制第一轮已保存的用户/助手消息，关闭读取事务，再请求模型。模型失败保留首条消息摘录；模型成功后重新授权并用旧标题作为更新条件，防止迟到结果覆盖新标题。标题调用与聊天回复解耦，既不让模型等待占用事务，也不使辅助功能失败遮盖已经完成的回答。

工作台已经支持笔形入口、首次发送创建 Task/Conversation、同一会话续聊及历史读取。创建响应丢失时可从任务列表找回已提交的空任务，仍未提供服务端创建幂等。证据：task_workspace.py、test_task_workspace.py、workspace-task.mjs；覆盖标题失败回退、重复总结跳过及迟到标题条件更新。参考答案已整理、尚未模拟，优先级高。本轮由教练按用户授权实现，不等于学习者独立掌握。
