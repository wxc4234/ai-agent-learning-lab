# ChatSearch：技能输入如何保持请求、历史与重答一致？

> 优先级：P0｜参考答案已整理、尚未模拟｜工作项目前端复盘。证据 F1/F2/F3 见[源码基线](chatsearch-source-baseline.md)。
> 本页保留 4 道技能输入契约题。后端 Skill 加载、Agent 执行、Checkpoint 与工具调度的最新事实统一见 [AI 全栈面试题与知识核对](chatsearch-ai-fullstack-interview.md)；前端输入契约不能代替后端执行权限，也不归入 Learning Lab 的实现证据。

## 1. 为什么技能不能只替换成一段 Prompt？

**参考回答：** 技能既有可见名称，也有 skillId/packageId 身份和在用户原文中的位置。当前保留 user_query，派生加斜杠的 query 和带技能列表前缀的 skill_marked_query。原文负责展示与重答，派生文本负责协议，快照负责身份；从显示名称或已加工文本反推身份会遇到重名、重复前缀和历史漂移。

**追问与答案：** 为什么只保存 skillId 还不够？用户会在正文中多次提同名词，选中位置影响展示与改写。当前 splitSkillQuery 校验身份非空、名称切片匹配、区间边界与不重叠；这些校验不是后端权限认证，执行时仍应验证技能可用性和访问权限。

**失败与验收建议：** 同名技能、正文普通同名词、空原文、重复重答、技能已删除。断言原文不被污染，前端快照不赋予服务端执行权限。

## 2. 为什么中文能用但 emoji 会坏？

**参考回答：** 当前坐标是所有 TEXT 直接拼接后的 UTF-16 左闭右开区间，不包括附件。JavaScript 切片按 UTF-16 code unit，而 Go 字节/rune、Python 字符索引可能使用不同单位；emoji 还可能由代理对或多个码点组成。F1 明确拒绝切在代理对中间，后端消费坐标时必须沿用同一协议或显式转换。

**追问与答案：** 半开区间有什么好处？长度为 end-start，右边界可等于原文长度，拼接更直接；不能因此忽略 Unicode 单位。当前代理对校验也不等于完整 grapheme cluster 分词。

**失败与验收建议：** 技能前有 emoji、跨两个 TEXT、附件夹在中间、重叠或越界、组合字符。历史入口仅做已有旧闭区间兼容，不能让新请求同时接受含糊的两套坐标。

## 3. 上传、重答与当前输入框为什么会产生竞态？

**参考回答：** F2 先等上传，再用本轮快照准备请求；复制快照避免后续修改污染旧轮次。上传失败仍交给原链路，不拿未完成附件抢发请求。重答从对应 question 的文本项读取快照，不读当前输入框，也不假设第一项就是文本；显式空技能列表优先，防止恢复已清除的技能。

**追问与答案：** 技能校验失败直接清空整条问题吗？当前恢复明确保存的原文并去掉失配技能元数据，保留附件；不猜测截断前缀。产品是否允许降级普通问答是业务选择，与“上传失败也强行降级发送”不同。

**失败与验收建议：** 旧轮重答时输入框已换技能、附件在第一项、上传后文本形状变化、重复预处理。现有 `skill-conversation.spec.ts` 有相关覆盖源码，本次未执行；浏览器全入口成功也不能只用纯函数测试替代。

## 4. 技能注入、Tool Calling 和 MCP 是一回事吗？

**参考回答：** 技能快照表达用户选择与提示上下文；Tool Calling 是模型提出结构化工具请求；MCP 是工具/资源交互协议。输入框展示技能不证明工具已注册，Schema 校验不证明当前用户有执行权限，模型选择工具更不等于副作用已完成。

**追问与答案：** 怎样防提示注入？把技能内容和外部文档当数据，执行权限由服务端可信上下文、工具白名单和参数约束控制；危险写入需要相应批准与幂等。不能靠“忽略恶意指令”一句提示实现隔离。
