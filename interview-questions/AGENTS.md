# 面试题库目录规则

## 模拟面试自动入口

当用户在 `interview-questions/` 目录下提出以下意图时，先读取本目录的 [`prompt.md`](prompt.md)，再执行对应动作：

- “开始模拟面试”“开始一面/二面/三面”“模拟大厂面试”
- “继续面试”“暂停”“给我提示”“结束面试”
- “复盘刚才的回答”“优化回答”“归档回答”“更新题库”

读取范围按需收敛，避免无关内容进入上下文：

1. 先读取 `prompt.md`，获取面试流程、追问、评分和归档规则；
2. 如果用户指定了项目，只读取对应的 `projects/` 文件及其关联题目；
3. 如果用户指定方向，只读取对应的 `algorithms/`、`frontend/`、`backend/`、`ai/`、`system-design/` 或 `behavioral/` 子目录中的相关文件；
4. 用户没有指定方向时，优先读取 `projects/README.md`、`interview-questions/README.md` 和与当前岗位最相关的少量题目，不要一次性加载整个题库。

## 模式识别

- 用户说“开始/继续”时进入面试官模式：一次只问一个问题，不提前给答案或评分。
- 用户说“提示”时只给当前问题的一条递进提示。
- 用户说“暂停”时保存当前阶段、已问问题和下一问。
- 用户说“结束面试”时输出评分、风险、优化后的回答和待归档清单。
- 用户说“归档/更新题库”时，按 `prompt.md` 的映射把优化后的问题与回答写入对应文件，并同步 README 索引。

## 事实边界

- 只能使用用户提供的简历、项目文件和对话中确认的事实，不得编造职责、指标、公司信息或项目结果。
- 没有真实指标时，记录验证方法和待补证据。
- 公开面经需要补充时，使用 Google 可核验来源，并在文档记录链接和日期。

## Token 使用约定

不要求每轮重新读取全部题库。优先复用当前对话已经读取的文件，只在切换项目、方向或进入归档阶段时补读必要文件。
