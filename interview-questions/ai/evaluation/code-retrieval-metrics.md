# 代码检索指标高，为什么仍可能找不全来源或答错？

复习优先级：高。参考答案已整理、尚未模拟。

**参考答案**：Recall@K衡量相关来源的覆盖率，MRR@K只关心首个相关项排在多前。跨文件任务可能需要三个定义，即使首个在第一名、MRR为1，Recall仍可能只有1/3。首先固定评测单位和候选去重规则，本项目按来源ID首次出现去重再截K，不能直接对比另一个按原始chunk排名计算的报告。gold分母必须完整，不能随K缩小。

检索失败不能从平均里丢掉：有答案问题失败按Recall/RR为0，否则不稳定的系统反而得高分。明确无答案问题没有可除的gold数量，单独计算假阳性并记录失败；null不等于0，也不能让失败冒充正确拒答。所有问题必须有一条结果，未知ID/错误版本/非法来源整次拒绝，合法但不相关的结果才按负例评分。

引用还要分层检查：文件哈希和行号正确是定位证据，引用来自本次Top K是来源支撑，命中gold是人工定义的相关性；三者都成立仍不代表最终答案的推理或表述正确。本课基线引用只是检索首项定位，必须标为retrieval_reference，不能当作模型回答引用正确率。无引用也不能报告100%正确。

**失败场景与取舍**：词面算法能命中符号，却漏掉纯中文需求，并因共享request一词给不存在的gzip功能返回结果。小型教练任务集既用于开发又用于回归，分数可用于发现实现变化，不能声称泛化效果；改gold不应改变排序，版本哈希应绑定查询、gold和文件字节。指标框架先保持离线、确定性与透明，真实向量、延迟/成本及独立留出集后续另测。

**项目证据**：[评测口径与手算案例](../../../docs/code-retrieval-evaluation.md)、[任务集](../../../apps/api/evaluations/code_retrieval/v1/dataset.json)、[基准报告](../../../apps/api/evaluations/code_retrieval/v1/baseline-report.json)、[53项专项](../../../apps/api/tests/workspace/files/test_code_retrieval_evaluation.py)。核心/标注/测试由教练按当课授权完成，不代表学习者已独立掌握或通过模拟面试。


**向量对照补充（高优先级，参考答案已整理、尚未模拟）**：为什么真实pgvector返回了Top K，仍可能不是答案？最近距离只表示相对排序，没有自动提供拒答阈值。当前受控特征比较里两个无答案问题均有返回，词面基线有一个假阳性；不能把向量结果非空当命中。比较前先校验同一任务集/源码版本、来源ID和候选粒度；本课取完整单批候选再按来源去重截K，拒绝未知/重复/分片错配，避免表面相同K其实分母与候选不同。真实数据库只证明SQL/授权/持久化边界，固定哈希向量不证明自然语言语义。供应商失败与授权版本拒绝保留为失败题，评测映射错配则整次拒绝，防止把坏数据计成普通漏检。证据：[17项真实PG/受控HTTPX](../../../apps/api/tests/workspace/files/test_code_vector_evaluation.py)、[固定比较报告](../../../apps/api/evaluations/code_retrieval/v1/vector-comparison.json)。


**RRF补充（高优先级，参考答案已整理、尚未模拟）**：为什么不直接相加词面得分与余弦距离？它们的方向和尺度不同，RRF用各路排名的`1/(c+rank)`相加，避免直接混合未校准分数；公式依据[Cormack等原论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)。本项目每路先按来源去重，缺失贡献0，分数相等按来源ID稳定排序；使用精确分数，不能靠浮点误差决定并列。常量c控制头部名次差异，和返回数量K不同，不能用留出验收标签调优。一路失败是缺少一路证据，本课保留整题失败；成功空结果才可让另一路正常贡献。不同降级策略会改变可用性和指标，必须显式报告。融合仍是排序，不保证候选相关或支持拒答；本项目无答案假阳性仍为2/2。证据：[融合协议与手算案例](../../../docs/code-retrieval-evaluation.md#rrf离线融合对照)、[固定三策略报告](../../../apps/api/evaluations/code_retrieval/v1/rrf-comparison.json)，28项新增通过；当前仅离线受控工程证据。

**拒答与数据泄漏补充（高优先级，参考答案已整理、尚未模拟）**：为什么开发集零假阳性不能证明拒答有效？开发集用于选择参数，选择过程已经利用其标签；需要先冻结规则/搜索网格/目标/参数，再用未参与选择的问题评估。当前开发选阈值2，在留出仍出现中文误拒答和标识符重合导致的误保留，说明英文词重合只是一种有限代理指标。不能继续用同一留出集调参并称为独立验证，后续迭代应另建留出版本。冻结文件和角色检查只能提供工程约束，不能证明人没有看过数据；共享小语料、教练编题也限制泛化结论。检索错误、无候选、主动拒答分别统计，避免把服务失败当作正确无答案。正例召回和负例假阳性的平衡损失避免依赖两类数量占比，但等权是实验选择，并不代表产品误拒答与误接受的真实代价。证据：[冻结流程和真实结果](../../../docs/code-retrieval-evaluation.md#无答案判定与开发留出评测)、[30项专项入口](../../../apps/api/tests/workspace/files/test_code_abstention_evaluation.py)及[PG两阶段测试](../../../apps/api/tests/workspace/files/test_code_abstention_comparison.py)。工程通过不等于独立掌握。

**耗时与用量补充（高优先级，参考答案已整理、尚未模拟）**：为什么各阶段P95不能相加？分位来自不同样本排序，慢请求未必是同一题；嵌套区间还会重复计数，应直接测端到端分布，附状态和样本数。当前8题P95等于最大值，不能推断稳定的尾延迟。异常样本只统计成功会产生幸存者偏差，取消后未执行的问题也不能填0。生成成功而数据库召回失败时，模型费用不会回滚；建库与查询用量应分别累计，缺失用量保持unknown，有已报告Token也不等于知道价格或最终账单。传输尝试只证明进入本地传输，不能证明供应商接收。证据：[观测口径/样本/22项测试](../../../docs/code-retrieval-evaluation.md#延迟与模型用量观测)。由教练按当课授权完成，不代表独立掌握。
