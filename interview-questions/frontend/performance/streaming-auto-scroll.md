# AI 内容持续增长时，如何在自动跟随和用户主动滚动之间正确切换？

> 主题：性能 / 滚动体验 | 频率：高 | 关联项目：[ChatSearch AI](../../projects/chatsearch-overview.md)

## 考点（面试官在考察什么）

- 指标口径、瓶颈定位、优化方案与验证闭环。

## 核心答案（能直接讲出口的版本）

我们把这个能力拆成三部分：生成时自动对齐、识别用户主动离开底部，以及用户回到底部后恢复跟随。PC 和 Wise 的主要差异在于，如何区分“用户真实手势”与“内容自然增长引起的滚动事件”。

自动对齐由 `BottomAlignController` 管理。开启后，它使用 `ResizeObserver` 监听整个回答内容区 `scrollContent` 的尺寸变化。回答增长时，先计算内容底部、可视区底部和理想滚动位置，再放到 `requestAnimationFrame` 中执行滚动，避免在 `ResizeObserver` 回调中立即反复读写布局。

滚动方式不是一律使用 smooth。目标位置与上次位置的差超过 `50px` 时使用 `smooth`，小距离使用 `instant`；如果异步帧执行时发现页面已经越过目标位置，也会立即定位，避免 iOS Safari 取消 smooth 动画时产生异常 scroll 事件。另外，当正文增长到产品要求的一屏高度后，控制器会主动停止底对齐，而不是无限强制追着最底部。

当用户主动向上查看历史内容时，需要立即停止自动对齐，否则下一次内容增长会把用户拉回去。PC 不用普通 `scroll` 事件判断，而是监听 `wheel`；当 `deltaY < 0` 时，表示用户通过鼠标滚轮或触控板向上滚动，此时调用 `stopBottomAlign`。需要注意，`deltaY > 0` 是向下滚动，面试时不能把方向说反。

Wise 上通过滚动位置判断。控制器记录过程中的最大 `maxScrollY`，当当前位置比历史最大值向上偏移超过 `5px`，且当前 `scrollHeight` 没有比之前变小时，才认为是用户真实上滑并停止对齐。额外校验 `scrollHeight` 是为了避免 Markdown 展开后又收缩等布局变化被误判为用户手势。

`stopBottomAlign` 会对 `scrollContent` 执行 `unobserve`，清空 observer 和滚动基线，并设置一个 `800ms` 的停止冷却期，避免刚关闭就被后续事件立即重开。

自动跟随不会仅因为页面发生了一次 scroll 就恢复。PC 在关闭后改为监听 wheel，当用户向底部滚动，且 `contentHasOverflow()` 判断内容底部已经回到可视区阈值内时，再重新开启底对齐。

Wise 的恢复条件更严格：必须先收到真实 `touchstart`，然后监测到滚动位置向下增大，同时内容已接近底部、当前 observer 未开启，并且已经越过 `800ms` 冷却期，才会重新恢复。这样可以避免回答自身增长或文创表格抖动触发的 scroll 事件误开自动跟随。

此外，当页面距离底部较远时，业务层会显示“回到底部”按钮。用户点击后使用 `instant` 直接到达底部，再显式调用 `startBottomAlign`恢复自动跟随。这里不用 smooth，是为了避免距离过长时滚动动画还未结束，新内容继续增长又触发停止对齐。

整体上，这套机制的核心不是简单地“只要没在底部就停止”，而是通过输入事件、滚动方向、布局高度和底部距离共同判断用户意图，在“持续看最新内容”和“主动查看历史”之间稳定切换。

## 简化记忆

- **自动跟随**：`ResizeObserver` 监听内容高度，`requestAnimationFrame` 内更新滚动位置。
- **滚动策略**：大于 `50px` 使用 smooth，小距离或回退使用 instant。
- **PC 停止**：`wheel.deltaY < 0` 表示用户向上查看。
- **Wise 停止**：向上超过 `5px` 并结合 `scrollHeight` 排除布局收缩误判。
- **Wise 恢复**：真实 `touchstart` + 向下滚动 + 接近底部 + 越过冷却期。
- **主动置底**：按钮 instant 到底，再显式恢复底对齐。

## 容易说错的地方

- PC 上向上滚动的判断是 `deltaY < 0`，不是 `deltaY > 0`。
- 暂停不只是设置布尔值，实际会停止观察 `scrollContent` 并移除相关事件监听。
- Wise 不能只靠 scroll 事件恢复，否则内容增长和布局抖动会产生误判。
