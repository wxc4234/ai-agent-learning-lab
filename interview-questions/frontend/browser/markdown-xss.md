# AI 返回的 Markdown 如何防止 XSS，同时保留必要的富文本能力？

> 主题：浏览器 / 安全 | 频率：高

## 考点（面试官在考察什么）

- 浏览器机制、生命周期、安全边界与异常场景。

## 核心答案（能直接讲出口的版本）

AI 返回的 Markdown 一律视为不可信数据，安全边界放在写入 DOM 之前。项目主链路不直接使用 `innerHTML`，而是统一经过 `@baidu/cosmic-dqa/markdown` 解析，并由底层 `parser.safeHtml` 过滤。

首先只开放标题、列表、表格和代码块等必要语法。原始 HTML 默认禁用或按白名单过滤，删除 script、iframe、事件属性和内联 SVG 等危险内容；代码块始终作为文本展示，不能执行。

链接和图片地址需要单独校验协议，只允许可信的 HTTP/HTTPS，拒绝 `javascript:`、`vbscript:` 和可执行的 `data:` 地址；外链增加 `noopener noreferrer`，图片尽量通过可信域名或图片代理加载。

流式场景不能逐 chunk 独立清洗，因为危险标签可能跨包拆分。前端保存累计 Markdown，在批量刷新时重新解析当前完整内容，统一净化后再更新 DOM，不能把新 chunk 直接拼入 `innerHTML`。

Mermaid、动态图表和业务组件属于独立安全边界：模型只下发结构化数据，由前端受控组件渲染，不能直接执行任意 SVG 或脚本；确需运行动态内容时使用 sandbox iframe，并通过 CSP 形成兜底。

## 防护速记

`Markdown 语法白名单 → HTML 净化 → URL 协议校验 → 累计内容重新解析 → 结构化组件渲染 → CSP 兜底。`

## 容易说错的地方

- Markdown 解析器不天然等于安全过滤器，必须确认净化发生在 DOM 写入之前。
- 流式 chunk 不是独立安全单元，跨 chunk 拼接后可能形成完整攻击载荷。
- 代码高亮只负责展示，不应执行代码块内容。
- CSP 是纵深防御，不能替代输入净化和 URL 校验。
