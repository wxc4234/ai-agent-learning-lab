# 一条 SSE 交叉返回 A/B 两个答案分支时，如何保证数据归属、完成状态和用户选择互不污染？

> 主题：Agent UI / 状态一致性 | 频率：高 | 关联项目：[ChatSearch AI](../../projects/chatsearch-ab-consistency.md)

## 考点（面试官在考察什么）

- 流式状态、时序边界、异常收口与项目真实性。

## 核心答案（能直接讲出口的版本）

核心是把**数据归属、当前浏览和最终选择**拆开维护。

一条 SSE 虽然会交叉返回 A、B 两个分支，但每个包都有 `compareIdx`，前端始终按它写入对应 Answer，而不是按用户当前浏览的列写入，所以切换浏览不会造成串包。

完成状态也按分支独立记录。A、B 分别维护 SSE 是否结束和 DOM 是否完成；只有两个分支都满足这两个条件，才通过统一完成入口触发一次 `answer-end`，整轮从 `generating` 进入 `awaiting_selection`。入口有终态守卫，因此重复或迟到的 finished 回调不会重复执行完成逻辑。

用户真实选择后才写入 `selectedIndex`，整轮进入 `selected`，并上报对应的 `sessionId` 和 `compareIdx`。

异常时，用户停止和网络失败最终都会进入 `awaiting_selection` 并开放选择，但上报语义不同：用户主动停止会设置 `compareAbortedByUser`，选择只用于前端收敛，不作为偏好上报；网络异常会先尝试两次续传，仍失败后中止未完成分支，用户之后的选择仍可正常上报。

## 状态速记

`compareIdx` 定归属，分支双屏障定完成，`selectedIndex` 定选择；所有完成回调收口到带终态守卫的统一入口。

## 容易说错的地方

- 回包按 `compareIdx` 归属，不按当前浏览列归属。
- SSE 结束不等于整轮完成，还要等待两个分支的 DOM 完成。
- 停止和异常后都会开放选择；用户主动停止后的选择不作为偏好上报。
