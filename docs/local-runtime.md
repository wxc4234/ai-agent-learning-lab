# 本地优先 PC Coding Agent

2026-09-15 用户确认调整产品路线，并授权教练直接完成本次实现。工程验收不代表学习者已经独立掌握，下次课程先结合这些实际代码解释关键边界，再恢复学习者亲手实现核心功能。

## 是什么

Web UI、FastAPI 与 Agent Runtime 在用户电脑运行，浏览器打开本机地址。模型仍可使用用户自己的云端 API，因此本地运行不等于离线；选入上下文的代码会发给模型服务。域名用于介绍、演示、文档与下载，公开执行服务不再是必做主线。

## 为什么仍有本机身份与内部凭证

界面不要求注册登录，但 Workspace、会话和 Run 已经通过 User 外键关联。使用稳定的 `local-owner-v1` 本机身份可以复用已有归属检查和持久化，不必把权限过滤整体移除。原账号数据保留、不会合并到本机用户；相同安装实例下不同浏览器共享本机数据，这不是多租户服务。

浏览器不持有内部凭证。BFF 从服务端环境变量注入 `X-Local-Runtime-Token`，后端先验证再解析本机身份；请求方自带的内部头和 Cookie 都不能选择身份。不同来源请求、远程后端配置和不合法凭证会被拒绝。Web/API 与数据库端口仅绑定回环地址。这些是本地访问边界，并不构成文件执行 Sandbox，后续仍要实现目录约束与命令审批。

## 怎么使用

1. 按 ENVIRONMENT.md 安装 Python/Node 依赖，准备 PostgreSQL/Redis 并执行 Alembic 迁移。
2. 在根目录 `.env` 配置自己的模型 API Key。
3. 在仓库根目录运行 `.venv/bin/python scripts/run_local.py`，浏览器访问 `http://127.0.0.1:3000`。
4. 直接聊天、取消或创建 Workspace。当前创建保存的是名称和归属，尚未绑定真实项目目录。

启动器先执行 `setup_local.py`，生成 32 字节随机凭证，保留原凭证重复使用，同步根目录 `.env` 与 `apps/web/.env.local`。不打印密钥、不删除数据库、不改写模型凭证。配置生效需要重启进程。当前是源码本地版，尚无桌面安装包或自动依赖安装。

`APP_MODE=account` 保留原账号模式。切换时两端必须一致并重启；本地模式凭证只用于本机边界，不能当作公网认证方案。账号模式下原账号资源继续按登录用户隔离，本地记录不会自动转移给某个账号。

## 示例与代码阅读顺序

浏览器创建 Workspace → BFF 检查 Origin/JSON → 注入本地内部凭证 → API 全局边界验证 → CurrentUser 创建或读取本机身份 → Workspace 服务提交 → 页面显示安全成功结果。

- `apps/api/app/local_boundary.py`：Host、来源与内部凭证检查，本地关闭账号变更接口。
- `apps/api/app/services/auth/local_identity.py`：PostgreSQL ON CONFLICT 处理并发初始化，事务提交后返回普通身份快照。
- `apps/api/app/dependencies.py`：本地与账号身份解析分支；业务仓储不感知登录形式。
- `apps/web/src/app/api/_shared/runtime.ts`：服务端模式判断与凭证注入，不应从客户端导入。
- `apps/web/src/features/workspaces/components/create-workspace.tsx`：ref 阻止重复提交，组件卸载取消等待，区分拒绝/成功/结果未确认。

## 安装成本与分发验收

最终分发目标：普通体验者无需手动安装或维护 Docker、PostgreSQL、Redis；由产品内嵌存储、替代实现或受管理的运行依赖提供能力。当前源码版尚未达到此目标。存储/取消机制调整必须验证迁移、事务、备份恢复和跨进程行为，不能把数据库文件替换等同于完成适配。

当前开发方式需要 PostgreSQL 与 Redis，Docker Compose 是推荐启动方式而不是代码运行的硬性要求；用户也可自行提供兼容服务。交付阶段优先降低普通体验者的安装成本，开发/服务端版本可继续保留原技术栈。不要为完成当前列表课提前切换存储。

统一安装入口要求：检测受支持 OS/架构与已有依赖，安装缺失运行依赖，生成仅本机保存的配置，执行迁移和健康检查，再启动页面；支持重复运行、明确失败提示和升级/卸载，卸载默认保留用户数据。系统授权和模型 API Key 配置可能仍需用户完成。当前 setup_local.py 只同步配置、run_local.py 只启动服务，尚不具备自动安装全部依赖的能力。


## 系统项目目录选择

工作台选择项目后点击“选择项目目录”，在系统窗口中选择文件夹；本地 API 校验真实路径并自动保存，不需要输入绝对路径或额外点击绑定。取消窗口返回 204，不改变项目；异常结果先重新读取状态，不自动重开窗口或重发保存。

当前适配 macOS 的系统目录窗口（osascript）和 Windows 的 FolderBrowserDialog（系统 PowerShell STA）。API 必须由当前登录桌面用户在本机启动；无桌面会话、容器内服务或其他系统会给出不可用/不支持提示。无需安装新的 Python/Node 依赖。Windows 原生交互尚待实机验证。

POST /workspaces/{workspace_id}/directory/select 只接受空 JSON，通过本地凭证、Origin 和资源归属校验后才打开窗口。选择期间没有数据库事务；保存时重新授权并加行锁。系统窗口等待 120 秒，BFF 130 秒，页面 140 秒。同一本地 API 进程只允许一个选择窗口；本地主流程按单 worker 启动，尚不提供跨进程窗口互斥。浏览器中断不代表后台事务已取消，仍须通过读取确认结果。

浏览器的目录上传控件只提供相对路径/文件内容，不能代替本地 Runtime 的绝对目录绑定；这里选择目录不会上传目录文件。
