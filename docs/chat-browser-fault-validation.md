# 聊天浏览器故障验收

验收日期：2026-09-11。主仓库 main，工作区包含尚未提交的失败摘要与卡片改动。

## 环境与方法

- macOS，Chrome 152.0.7977.83。
- 浏览器访问 `http://localhost:3000`，BFF 连接本机 FastAPI `127.0.0.1:8000`。
- 通过 CDP 操作本地测试标签；读取实际页面文案、输入禁用状态与摘要 DOM。
- 请求前离线使用 `Network.emulateNetworkConditions`，完成后恢复在线。
- HTTP 429 使用 `Fetch` 拦截一次 `/api/chat/stream` 请求并返回 429；完成后禁用拦截。此项只验证浏览器 HTTP 错误处理，未经过真实服务端限流器。
- 恢复重试使用真实后端与模型请求，不伪造成功结果。

## 发现的传输边界

`apps/api/app/services/model/model_decision.py` 当前模型请求使用 `stream=False`。`chat_service.py` 将完整 reply 放入一个 `TEXT_MESSAGE_CONTENT`，随后发送文本结束和运行终态。因此当前接口是 NDJSON 领域事件流，不能描述成模型逐 Token 实时输出。浏览器解析器支持任意网络分块，并不意味着后端逐 Token 生产内容。

请求完成后再离线不属于流中断测试。低速传输也不保证每条 NDJSON 事件分别触发可观察的页面渲染。本轮未据此修改业务代码，也未扩大为模型流式输出改造。

## 未覆盖项

- 文本可见但终态未到达时的浏览器真实断流及其重试，仍需补充证据或受控分段响应复现。
- 真正的 Redis/服务端限流、Retry-After 倒计时、服务端幂等均不在本次模拟 429 的证明范围内。
- 浏览器断开不等于证明服务端事务回滚；本轮未核查各失败请求的数据库终态。

本轮未修改业务源码；沿用上一轮 71 条测试、类型检查和 lint 的通过记录，没有把旧检查冒称为本轮重新运行。
